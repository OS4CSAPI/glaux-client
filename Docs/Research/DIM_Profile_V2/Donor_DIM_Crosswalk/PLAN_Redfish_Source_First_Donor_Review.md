## One bounded execution through verified publication

1. **Discover the donor's own organization.** Inventory the 2025.2 schema families using the publisher index. Record a reason for any family grouped as assessed, illustrative, outside equipment scope, or held for a particular question. Include in-scope information outside the starting set above. Follow relevant definitions for components, location, assembly, inventory, status, telemetry, power and capabilities when they establish a distinct meaning. Record release, exact schema version, JSON pointer, member or group IDs, and actual reading depth. Distinguish schemas, protocol requirements, examples and deployment evidence. Preserve the 2025.3 companion separately. Save the inventory and initial findings in the source ledger before integration.
2. **Compare in both directions.** For each in-scope native group, compare its subject and meaning against the current master and record a match, clarification, new information need, implementation detail, or specific hold. For each proposed addition, identify the nearest existing row and explain what would be lost by using it. Give every baseline row and every addition an explicit Redfish disposition, including the scope of a negative assessment. Check plausible overlaps with previous donors. Trace one documentary example distinguishing the manager's physical location, the equipment it manages, and the subject of a sensor reading. Identify the evidence needed to connect those facts to a real unit.
3. **Publish and finish.** Integrate established findings into the same editable master, canonical JSON, both CSVs, both readable tables and donor-group comparison. Preserve earlier cells, row IDs, cases, dividers, donor order, manual M00/M01 and the browsable pre-change workbook. Use the existing classification colors. Record explicit statuses for prior donors on new rows. Verify the saved grid, fills, unaffected cells and package parts, 26 sheets, row-only freeze and actual workbook reopening. Read back the published workbook, compare its fingerprint and check the GitHub result. Report what the donor adds, where prior donors already suffice and the scope limits that affect interpretation.
