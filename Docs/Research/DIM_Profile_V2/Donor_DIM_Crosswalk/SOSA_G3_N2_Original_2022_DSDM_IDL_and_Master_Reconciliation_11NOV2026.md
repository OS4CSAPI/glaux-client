## Source-native meanings verified for the whole sensing-system question

The model distinguishes Sensor and SensorComponent association (§§1.1.3.89/.92); a Component_ may be hardware or software (§1.1.3.15), while Module_ and ModuleImplementation express distinct roles (§§1.1.3.68–69). Platform and HostPlatform express a source-specific physical installation relation (§§1.1.3.54/.78), not a universal cross-vendor chassis. Component_ explicitly carries health, operational state, mode, name, version and address; Sensor has separate health/operational/configuration state. DIV-2 `GeneralHealthStateEnum` (§1.2.22) enumerates HEALTHY/CRITICAL/DEGRADED, whereas `GeneralOperationalState` (§1.2.23) has a different lifecycle-state set; mode enumerations are separate. **Source field cardinalities are original source constraints for that 2022 native model, not adopted general DIM cardinalities.**

The original DIV-3 messages distinguish Get Sensor Health (§1.3.2.32), Get Sensor Mode (§1.3.2.34), Get Sensor State (§1.3.2.35), Get System Manager Config (§1.3.2.37), Restart Sensor (§1.3.2.38), and Update Mode (§1.3.2.47). Their original request/response templates have different native payloads; for example, Restart Sensor's response is documented as header-only, and `UpdateMode_Request.idl` has a typed `ComponentMode_Info` field. `SensorHealth_Info.idl` contains separately typed sensor and component health information, while `SensorComponent_Info.idl` includes source component ID, name, type and in-band URI. **These original native 2022 message structures do NOT establish a live OGC API – Connected Systems (CSAPI) Command endpoint or a 2023 C239 REST/OpenAPI contract.**

Other source-specific distinctions include network topology and IPv4 interface representation (§§1.1.3.70–74); electrical PowerBus/PowerPort relation (§§1.1.3.80–81), which gives no battery-reserve reporting; and `AntennaInstallation` (§1.1.3.3) positions an antenna in a vehicle frame without proving actual reported device pose. The source `SensorBITResult` and `BitResults_Info.idl` include diagnostic-result concepts; `LogEntry` time is typed in POSIX seconds (§1.2.55), but this is **not** automatically an event occurrence timestamp. SignalDetection and SignalCharacterization include source-specific confidence rather than a generic uncertainty quantity.
