## 2. Native construct and parameter meanings

**AMPS is a hardware module-profile name grammar, not an API data schema.** Figure13.3.3-1 presents the Alternate Module Profile Scheme (AMPS) naming string with form factor/clock modifiers, the OpenVPX module-profile section, distinct Alternate Naming Structure (ANS) and slot-profile dash positions, depth/cooling/pitch, and groups of hardware-port protocol fields. The figure and text explicitly defer the full AMPS/ANS grammar, port-size repartition and normative details to ANSI/VITA 65.0 §§1.3.3.3.2 and 8.10. Consequently the bounded C239 summary does not independently establish all native ANSI/VITA conformance constraints, and the syntax must not be mapped to CSAPI JSON/SWE data record fields, a sensor measurement, a universal System hierarchy or live equipment capability.

**Table13.3.3-1 distinguishes 12 named AMPS parameter rows.** Its `u` specifies 3U/6U form factor, `y` clock termination/receive alternatives, `z.z.z` an OpenVPX profile section, `i` an ANS dash fixed to 1 *in this edition*, and `j` the separate Slot Profile dash, omitted if no dash options/aperture. Its `cLkm`, `c`, `Lkm`, `L`, `k` and `m` describe port counts, hardware protocol type/qualifiers and port-width modifiers, not an ISA custom data field or physical installed value. `dcp` captures physical depth/cooling/pitch as constrained by Tables13.3.3-5 and -6, rather than requiring every possible dimension/cooling/pitch cross-product.

**The number `c` is context-sensitive.** When the ANS field already defines multiple ports, `c` counts original pipe-size ports independently of repartitioning. When an ANS field defines a single port and the slot profile permits repartitioning, `c` and width modifiers can describe splitting an allocation, as with three PCIe Gen3 Fat Pipes (12 of 16 lanes used). Hardware port count is neither a physical sensor member count nor the cardinality of CSAPI Observations, commands or properties.
