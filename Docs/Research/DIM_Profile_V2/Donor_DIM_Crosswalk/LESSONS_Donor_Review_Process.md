## How to use and maintain this record

Add or change a lesson only when the ordinary research work provides evidence. Record what happened, the evidence, the resulting practice and where the practice applies. Do not write another lessons report after every prompt. The PITON links here instead of duplicating the entire lessons history.

**Observed** means the stated event occurred in this project. **Demonstrated benefit** means the practice produced a specific observed improvement. **Under test** means a proposed safeguard has not yet been exercised through the full semantic review. These are evidence descriptions, not permanent approval grades or universal rules.

At ISA-12, consolidate the practices demonstrated across the whole ISA correction into a reusable donor-review procedure and starter template. Adapt that procedure to the next donor's actual source form. Twelve passes and ISA's catalogue organization are not mandatory for other standards. A later finding can refine a practice without erasing completed work.

| **L01 — Start with the source inventory** | The earlier eleven-concept ISA selection omitted native Manufacturer, Model and Serial Number properties. | **L02 — Make empty cells intelligible** | A blank manufacturer cell was reasonably read as possible evidence that ISA lacked manufacturer identification. ISA-01 replaced twenty empty ISA cells with an explicit review state and assigned pass, while retaining eleven earlier terms for reconciliation. See [ISA review](ISA_Correction_Review_ISA01_07NOV2026.md). | Keep review coverage, mapping relationship and owner/model decision separate. Distinguish Not reviewed, a specific Question, and No correspondence found in a named source scope. | **Ambiguity observed; display improvement delivered.** Applicable to comparison matrices. A blank or unsuccessful keyword search is not proof that a donor lacks a representation. |
| **L03 — Follow entries across page boundaries** | Properties Zones and Zoom extend to printed p.18; observables Solar Radiation, Velocity and Verified By extend to printed p.22. Approximate boundaries in the initial plan would have excluded them. ISA-01 assigned them explicitly. See [boundary amendment](ISA01_Plan_Amendment_07NOV2026.md). | Assign named entries and read each definition to completion. Use page ranges for navigation, not as the definition of the review scope. | **Demonstrated benefit.** Especially important for shared pages, continued tables and cross-references. The same principle applies to split schema/module definitions. |
| **L04 — Check coverage separately from consistency** | Step15's workbook/evidence parity passed while manufacturer, model and serial number were absent from the selected records. ISA-01 therefore reconciled the source's contents, body and index, independently of the populated crosswalk cells. | Validate source coverage as well as file parity. The final semantic audit must start from original definitions and the source inventory, not merely compare one generated artifact with another. | **Prior limitation observed; inventory reconciliation demonstrated.** The full semantic closeout method is **under test** until ISA-12. Automated consistency checks cannot certify an interpretation's meaning. |
| **L05 — Bound work by assigned source content** | A selected eleven-mapping delivery was treated as the donor-review checkpoint without an inventory of the remaining work. ISA-01 now assigns all 480 catalogue entries, 279 source blocks, 31 existing row/topic targets and 25 earlier findings to review passes. | Finish a defined source block rather than a quota of interesting mappings. Split an oversized block openly, naming its remaining entries and next pass; never drop work to protect an iteration estimate. | **Failure observed; assigned-work safeguard established.** Batch sizing remains **under test** during ISA-02–11. Counts refer to different kinds of tracked records and must not be added together as a concept total. |
| **L06 — Keep unknowns and completed work local** | The source census was completed but publication remained separate. The owner also identified the risk of later chats treating broad cautionary wording as a reason to reopen completed work. See [current PITON](PITON_ISA_Coverage_Correction_07NOV2026.md). | Report completed tasks as complete when their tests pass. Attach an uncertainty to its exact record, evidence and resolving action. Track source review, model acceptance and repository publication separately. Reopen a record because of new evidence, not because an old generic caveat exists. | **Workflow problem observed; recovery rule established.** Applies to research continuity across chats. This is not permission to conceal unread sources or unsupported claims. |
| **L07 — Publish to the actual project repository** | ISA-01 was delivered as a sandbox-only package; the user had to repeat the standing requirement to publish documentation in GitHub. An interrupted artifact upload did not constitute a published checkpoint. | GitHub on the specified research branch is the durable project home. For each authorized delivery, commit the documents, source registers and workbook, update the current recovery pointers, and verify the committed paths and content. Sandbox files are additional copies, not substitutes. Never attribute access changes to a model switch without evidence. | **Observed delivery failure; corrective publication required and verified separately.** If one action is absent, discover the available supported write actions before declaring publication unavailable. A verified publication failure is a specific action to resolve, not a reason to redo completed research. |

## Practices still to test before promoting them as reusable defaults

The ISA correction must still demonstrate how well the chosen batch sizes handle dense definitions, how best to represent one-to-many or many-to-one semantic relationships without misleading rows, and how to present important source concepts that require additional or split DIM rows. The four equipment cases can challenge interpretations; they must not restrict discovery to features they happen to exhibit.

Do not call the twelve-iteration schedule a universal best practice. Do not confuse a source catalogue entry with a physical component, a required DIM row or an established mapping. Keep core definitions and source extension status distinct. Refine these practices when the source comparison provides evidence, not simply because the current plan recommends them.
