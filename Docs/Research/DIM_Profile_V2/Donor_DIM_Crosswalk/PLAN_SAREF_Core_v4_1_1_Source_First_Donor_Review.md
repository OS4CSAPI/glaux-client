## 2. Compare in both directions and deliver the workbook

1. **From SAREF to the master.** Give every native finding a disposition: existing row with qualified correspondence, clarified definition, new information need, native-only/outside scope with reason, or an explicit open question. If the closest row loses a distinction, name that row and explain what would disappear. Test another row, a clarification, or an addition. A contribution can be a relationship or rule as well as a field. Zero new rows and multiple new rows both require evidence.
2. **From the master to SAREF.** Give every baseline row and every warranted addition an explicit SAREF cell. Record exact/direct, partial, broader, narrower, related, conflicting, no established correspondence within the reviewed scope, or unreviewed with a specific reason. Group repeated outcomes by row ID, common rationale, evidence, and exceptions. Check positive mappings and apparent gaps, including rows introduced by later donors.
3. **Test the difficult distinctions.** Use evidence to distinguish a product kind from an individual unit, a particular device’s function from the service exposing it, a command from an execution, and the property of a particular feature from a reported value. Check what an axiom actually licenses one to infer. Where neither a statement nor an applicable axiom establishes a value, preserve the unknown. A publisher example demonstrates a pattern. Evidence about installed equipment must come from that equipment or its records. Use an existing equipment case where its documented facts distinguish competing mappings.
4. **Use the same classification rule as prior donors.** Record correspondence strength and candidate classification separately. Apply existing blue for common, amber for specialized, gray for native-only, purple for an unresolved candidate, or an explicit unfilled status for mixed/held or unassessed cases. Compare genuinely equivalent decisions across donors once and document justified differences. If a new row intersects another donor, use its existing evidence or state the remaining question. [Accepted classification practice](PLAN_F3_Cross_Donor_Classification_Fairness_14NOV2026.md#f3-owner-explanation-and-accepted-results)
5. **Integrate once a coherent set is ready.** Add one identified SAREF donor column within the donor group. Preserve the relative order of existing columns, stable IDs, group dividers, cases, grouped OGC foundation, and DIM at the right. Update the canonical JSON, both CSV mirrors, both readable comparisons, and the same editable workbook together. Preserve existing data, controls, and row-only freezing. On new rows, every previously completed donor column also needs explicit evidence or status.

**Integration recovery point.** Publish each coherent integration with exact row IDs, old/new values, classification changes, and mirror/workbook parity. Keep pending work visible in the existing recovery note if interrupted.
