# W3C Web of Things 1.1 donor research plan

**Decision to support.** What can a profile-aware Connected Systems client reliably tell a person about equipment, the interactions it exposes, and the intermediary presenting it? Compare the World Wide Web Consortium (W3C) donor with the 486 information rows at baseline `fe598e0`. Allow the donor to introduce a missing distinction, relationship or rule. The owner decides subsequent Domain Information Model (DIM) adoption.

**Execution budget.** One further Proceed authorizes the whole review below as one bounded assignment through publication. The three phases are internal checkpoints. The next owner decision is acceptance unless a material scope change requires direction.

## 1. Establish what the donor actually says

Start with the dated W3C Recommendations for [Thing Description 1.1](https://www.w3.org/TR/2023/REC-wot-thing-description11-20231205/), [Architecture 1.1](https://www.w3.org/TR/2023/REC-wot-architecture11-20231205/) and [Discovery](https://www.w3.org/TR/2023/REC-wot-discovery-20231205/). Treat Thing Description as the primary information model. Use Architecture for roles and mediation and Discovery for how descriptions are found and retrieved. Check the publisher’s errata and companion list once. Record the status and relevance of profiles, scripting, binding templates and implementation reports. Follow a companion or external vocabulary only to settle an identified meaning, with the exact dependency recorded.

Before matching rows, freeze an inventory by document, section, annex and linked model artifact. Read the applicable definitions, member tables, constraints, operations and inheritance in context. Reconcile machine-readable vocabulary, context and schema against the prose. Give each unit a stable ID, exact locator, native grouping, subject, meaning, normative standing, and actual contact (read, sampled, inaccessible, excluded with reason or unresolved). Account for figures and examples separately. Record the effect of any incomplete coverage.

## 2. Compare in both directions

| Direction | Required result |
|---|---|
| Donor to table | Dispose every inventoried concept or explicit group of members as an existing match, clarification, candidate new row, donor-specific detail, or open question. For each proposed addition name the nearest existing row, the distinction it loses, and an equipment use case. Zero additions is a valid finding when all distinct meanings are accounted for. |
| Table to donor | Assign every existing information row and warranted addition an explicit WoT status. Record direct, partial, broader, narrower, related, conflicting, no correspondence established within reviewed scope, or unreviewed with reason. Group repeated findings by exact row IDs and list exceptions. |
| Fairness across donors | Test equivalent cases once against prior evidence. Compare Thing Model, Thing Description and the described entity with SAREF DeviceKind, individual device, function and service. Examine properties, actions, events, data schemas, forms, links, security declarations and directory metadata on their own terms. Track the issuer of each meaning. |

Use one documented equipment case to test whether a client can distinguish a model from an instance, a proxy endpoint from physical identity, and an advertised action from evidence that it ran. Record what the client could display, what evidence supports it and what would remain unknown. Keep correspondence strength separate from the established common, specialized, native-only and unresolved color classes.

## 3. Integrate, verify and close

Preserve a browsable pre-change workbook checkpoint. Integrate supported results into canonical JSON, both CSV mirrors, both readable comparisons and the same editable Excel workbook. Keep stable IDs, donor order, 26 sheets, dividers and row-only freezing. Apply existing classification rules to all affected cells. Every previously completed donor needs an explicit status on new rows. Retain manual M00/M01 and existing holds and adoption gates.

Reconcile frozen IDs and final row counts once. Check saved texts, fills, mirror parity and preserved cells, open the workbook in Excel where available, and inspect the changed region for clipping or repair. Record the application tested and any limit. Verify publication with applicable checks and a fresh download matching the verified workbook fingerprint.

Publish the ledger, workbook link and a plain-English comparison explaining the native groupings, strongest contributions, overlap, rejected matches, new rows or reasons for zero, and each unresolved question with its impact. If key evidence is unavailable, close as bounded partial with exact affected IDs and the evidence needed to reopen them. Fix only identified discrepancies. At each substantive save update the PITON with published evidence, any local-only work and the first unfinished item. Resume there after interruption. Stop for the owner’s disposition.
