## 4. Particular separations that matter

- **CSAPI Part 1 versus Part 2** are distinct original standards; their native System/Procedure versus dynamic DataStream/Observation/Command scopes are not identical. The accepted *seven-donor* sample happened to use one combined CSAPI header; that was **layout approval**, not a source-roster decision.
- **SensorML 3.0**, **SWE Common 3.0** and **OMS 3.0** deserve independent source assessment rather than being counted as mere CSAPI duplicates.
- **OPC UA Devices** versus **PA-DIM** are separately identified. The earlier donor review did **not** fully establish PA-DIM's own fields. Avoid double counting inherited OPC nameplate properties.
- **W3C SOSA/SSN 2017 Recommendation** versus its **2026 draft** require edition-specific treatment. Neither is **The Open Group SOSA**, whose RA 1.1, DSDM 1.0, System Management API companion set and RA 2.0 snapshot have different scopes.
- **IEEE 1451.0-2024** must not absorb the distinct 1451.1 legacy NCAP information model or later MQTT variant. The 2024 normative text remains incompletely reviewed despite meaningful NIST/Playground public evidence.
- **NIEM Core/Model** and Intelligence/CBRN domains are distinct; **29 NIEM artifact records are not 29 automatic columns**.
- **Redfish** and **DMTF CIM**, **QUDT** and **UCUM**, and **IETF hardware**, **interfaces**, **network topology**, and **battery/energy** have meaningful boundaries to test, not compulsory combined columns.
- **W3C WoT Thing Description 1.1** is an important companion from older review but has **no distinct artifact ID in the 182-item baseline**; don't silently invent a 183rd. [Original donor discussion](../Concept_Donor_Comparison/Donor_Contributions.md) remains the appropriate historical pointer.
- **STANAG 4789** is an independent NATO sensor-interoperability standardization effort; it is recorded as context/implementation lineage. That does not make it subordinate to SAPIENT or an automatic universal DIM class hierarchy.

## 5. What is and isn't decided

**Decided for planning:** Original source titles, recorded versions, lineage distinction, and a provisional or conditional eligibility category for each candidate. All 182 artifacts are accounted for exactly once. The source family 13-developed/17-preliminary comparison was considered, not converted into false 182-artifact verification.

**NOT decided:** Which conditional donors earn actual columns; whether later source evaluation identifies a need to split or merge more families; the final **least-used → most-used** column order; any new donor-native concept-to-DIM alignment; any accepted DIM elements, UML classes or precise cardinalities.

**Final rank is `null` for EVERY candidate in the JSON/CSV.** The tables above are alphabetized *within their source-eligibility category* solely for navigation. A standard is not “least important” because it appears earlier here. Source-artifact count is not an indication of information-model importance.
