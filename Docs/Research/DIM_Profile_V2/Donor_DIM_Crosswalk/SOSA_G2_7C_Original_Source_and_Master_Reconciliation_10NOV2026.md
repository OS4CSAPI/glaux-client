## 2. Native grammar, physical role and legal-combination distinctions

**The original source says the summary tables provide Alternate Naming Structure (ANS) port order and corresponding legal protocols, not a generic software schema.** Copper backplane fields are parenthesized `(...)`; optical fields are enclosed in `[...]`; the SOSA-only radio-frequency (RF) pinout and XMC overlay portions use angle brackets `<...>`. These delimiters encode specialized physical module-profile and aperture arrangements, not the encoding of a SensorML description, SWE Common measurement, OGC API – Connected Systems response or a runtime connection negotiation. The original text points to ANSI/VITA 65.1 for the underlying ANS definition and refers to earlier Figure13.3.3-1; that external original is not independently audited here.

**The ten source families preserve equipment-specific physical distinctions.** The 3U table includes I/O-intensive, External I/O, Full-P Payload, Half-P Payload, RF/Optical Switch and Radial Clock roles. The 6U table separately names External I/O and three Payload variants: **P5:XMC**, **P5:Expansion Plane** and **P5:VITA 66/67**, corresponding to materially different physical P5 slot/overlay or aperture roles. None requires every sensing system to contain a 3U or 6U chassis, every card to have the same physical ports, or one profile family to become a generic DIM equipment class.

**Dash, dcp, RF, optical and XMC rows need source-qualified handling.** The matrix lists 23 3U and 16 6U dash options for named profile families; an asterisk indicates source **Legacy** for selected specific options, not blanket status for an entire system or proof of current certification expiry. The `F2C`, `F4C`, `F8H` and `S2E` dcp choices also concern card depth, physical cooling and slot pitch—not actual measured cooling, current configuration or installed module inventory. The source's `X` legend says **Not Applicable**; its multi-column position cannot be assumed accurately without the unavailable visual matrix audit.

## 3. Ten original full-string examples and source-text anomalies

**Table13.3.4-3 contains ten example AMPS strings**, one for each listed family, with detailed physical data/control/expansion port groups, the optical apertures and SOSA-only RF/XMC suffixes as applicable. These are examples of *format and physical profile naming*, not independently tested representations of installed PICs or field-verified manufacturer modules. Their full printed string identifiers are retained in the source ledger to support later exact reconciliation against ANSI/VITA originals.

Two anomalies are especially important. **The source prints `MODA3p-12.2.8-1-F2C-...` for the 6U External I/O example**, even though §13.3.3's `u` field distinguished 3U and 6U and other 6U examples use `MODA6p`; it is an unresolved original-source inconsistency, not a corrected code. The examples also print `RF1` and `4A2F` tokens whose complete semantics or permitted protocol use are not established by the previously reviewed C239 protocol-code dictionary alone. No rule, token expansion or equivalence is invented for those references; §13.3.8 and external native originals remain unread.

A related caveat concerns the **source-wide Payload heading**, which encompasses I/O-intensive, RF/Optical Switch and Radial Clock functions in the table. A section caption does not make those roles physically identical, let alone establish a mandatory universal DIM chassis/class taxonomy. Selected dash options carry an asterisk, but the source here does not establish actual removal in a future edition, product age or a failed device.
