## Plain-English research outcome

**The native object taxonomy is for things DETECTED, not the physical sensing equipment that is detecting them.** BSI §7 defines nine top-level target-class families, including Equipment, with subordinate classes such as Passive sensor and Camera; those are potential observed objects. No automatic physical component, product chassis, sensor inventory or CSAPI System classification follows from a label match. The classification probabilities and reserved "Other" case concern uncertainty and target type, not a generic missing metadata marker. BSI Table 97 independently lists ten target behaviours, including Active and Passive: these do **not** describe whether the observing sensor is turned on, armed or in an ISA operational state.

**The SAPIENT class extension mechanism is scoped, not a universal ontology.** §7.3 and original Figure7 show new object subclasses docking into existing core classes using namespaced extension declarations, with satellites, e-bikes and tanker ships presented as examples. Annex D lists possible DTIC/NATO/OWL/SKOS resources and a restricted AINTP-03 reference. None is, just by being cited, an incorporated, inspected native schema, exact OGC ObservedProperty, standardized equipment hierarchy or accepted DIM class.

**The Annexes expose useful optional integrations and significant exact limitations.** Annex C describes middleware routing, persistence, optional validation and source/destination mediation, as well as locally arranged file storage. It explicitly places streaming video **outside** BSI Flex 335, while Table C.1 provides only illustrative bandwidth guidance. SAPIENT source documents cannot therefore prove that a vendor's live video, file resources, storage, physical cables, connectivity adapters or historical-query service are natively standardized or verifiably operational.

**The informative examples must not become software test fixtures without correction and validation.** Annex B says its sample messages are JSON-like illustrations, while actual operational serialization is binary protobuf. The published TaskAck sample omits mandatory TaskStatus, the Alert sample uses a UUID-shaped alert ID where a ULID is required, and a Registration sample contains a legacy Command.name that the current v2 source removes. No validity or interoperability claim is inferred from those samples.
