## 2. Key native meaning boundaries

**Task and assignment:** Original §7.1.1 describes incoming externally originated task requests, followed by proposed internal Task Manager decomposition into module assignments. A `taskID` is not an `assignmentID`, and task state/status/health, receipt acknowledgment, assignment health, the RF MORA control interaction and an actual achieved hardware effect are separate. The tasking table is preliminary, not the source of a mandatory universal CSAPI CommandStream or ISA execution record.

**Radio-frequency source detail:** RF Conditioner-Receiver-Exciter (module 2.3) and Emitter/Collector (2.4) have overlapping services but different RF aperture roles, and the standard distinguishes MORA Device, Resource Manager and Signal Port Manager endpoint groups. A source-described coax/fiber analog interface and wideband digital/context alternative are design/interface possibilities, not independently observed field equipment or a universal physical chassis. Manufacturer/model/equipment-ID getters describe RF module interfaces, not verified values for the four studied source arrangements.

**Reference-only interpretation:** The module scope for Tracker, Signal/Object Characterizer, External Data Ingestor, Situation Assessor, Impact Assessor & Responder and Reporting Services is explicitly not defined in C239 Edition 1.1. Their SvcV-4 activity and I/O tables can inform a related/negative DIM crosswalk but cannot establish performed observations, report formats, traceable device identity, a deployed tasking API or mandatory model fields. Storage/Retrieval Manager is different because actual Rule 10.5-1–5 exists; those obligations remain strictly scoped to that module, with original external storage/crypto specifications still held.
