## 2. Source-native concept meanings

**Conditional 6U hardware and non-universal physical roles.** Rule13.2.12-1 applies *when* the hardware is an ANSI/VITA 65.0 **6U Plug-In Card (PIC)**. Its five permitted slot profiles distinguish two payload variants, a Data/Control switch, external I/O and an RF/optical-rich variant. This says nothing about mandatory 6U chassis for all sensing systems, one logical SOSA Module per physical card, or which actual commercial/fielded equipment is in the four source cases.

**Payload and actual backplane routing (§13.2.12.1).** One 6U payload design devotes P5/J5 to additional Expansion-plane connections, while a distinct design exposes **XMC** mappings for optional system-specific I/O. Rule13.2.12.1-1 forbids interslot routing of non-overlay XMC signals; Rule13.2.12.1-2 forbids interslot Control-plane Thin Pipes. Observation13.2.12.1-2 predicts typically one/two XMC-bearing cards, but **is nonnormative, not a fixed 6U chassis cardinality**. The recommendation favoring the non-XMC slot profile when XMC is unnecessary is source-defined SHOULD, not a generic CSAPI Profile requirement.

**Internal plane switches versus external data transport (§13.2.12.2).** The 6U switch profile separates Data and Control planes; C239 text labels two intended outbound Data Thin Pipes at **1000BASE-T**, and one outbound Control Ultra-Thin Pipe at **100BASE-T** on specified P6A/J6A pins. These are physical-port and signaling **design** descriptions. They do not assert a field IP address, accessible endpoint, current Ethernet connection, source-authenticated network observation or automatically implemented CSAPI request service.

**Platform-specific external I/O and command/status design (§13.2.12.3).** The 6U External I/O PIC can be subservient to up to four PICs via Expansion planes or receive commands from multiple PICs via the Control plane. Rule13.2.12.3-1 prohibits routing user-defined interslot backplane signals. Observation13.2.12.3-1 proposes an I/O aggregation pattern, **not** verified installed peripherals, a registered network mediator, an executed command, successful acknowledgement or measured hardware effect. Recommendation13.2.12.3-2 has potentially counterintuitive printed conditional wording and is preserved without rewriting its meaning.

**RF/optical variant and source maturity (§13.2.12.4).** The profile is described under an RF/Optical Switch heading yet its figure is captioned a 6U Payload slot profile, illustrating hardware roles whose marketing/heading labels are not a universal ontology. The source specifically qualifies this richer coax/optical use as **new and of limited deployment**. Table date, `Ready`, and legacy-marker variations are reference/design status, not live hardware state, verified availability or vendor conformance.
