## 1. What has actually been accomplished for a human operator

At Step 40, the shared Glaux Resource Details interface understood carefully prepared local project evidence packets. It did **not** know how to discover those meanings when given an unfamiliar producer's **native OGC API – Connected Systems (CSAPI)** resource URL. The separate Bennett live route used preselected resource identifiers and case-specific context; local packet test successes did not demonstrate a genuinely common native resource-to-Profile-to-UI route. [Step 40 fidelity scorecard](Step40_Four_Case_Source_to_Client_Fidelity_Scorecard_03NOV2026.md).

**This gap now has a real, bounded end-to-end demonstration:** an operator supplies an arbitrary read-only **native `Procedure` or `System` URL** in the **existing Resource Details profile-test page**. One new, vendor-independent Glaux loader GETs an actual `application/geo+json` native feature; checks its type, exact resource UID/self identity, actual HTTP and JSON `profile` and `describedby` links, project Profile version and resource-specific evidence link; GETs the separately versioned **PROJECT-owned source evidence**; rejects mismatched or unsupported evidence to a visible **raw-only native view**; otherwise feeds the source-qualified claims into **the same source-independent interpreter and existing Resource Details renderer** already proven across the four local research cases. Nothing selects special meaning from the word “Dragino,” “Bennett,” a known manufacturer or one preselected server UUID.

The existing page now contains a clearly identified native URL field and Load button, as well as a direct `native` query parameter for reproducible local browser tests. The native Feature and linked project evidence remain distinguishable in **Management → Record**. Printed examples are not actual telemetry, source fact and derived/unknown claims retain their standing, a source-original event remains distinct from digital copies, and the Map does not invent a position for an individual probe. HTTP access is read-only with no credentials, redirects disabled, HTTPS required except explicit local loopback HTTP, and the selected test contract requires same-origin Profile/evidence links. This is **bounded project contract support**, not an arbitrary RFC 8288 extension parser, full native OGC conformance certificate or publisher signature.
