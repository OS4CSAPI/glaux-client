## 1. Plain-language outcome

Previously, we had four carefully sourced local JSON packets that Glaux could interpret through one common component, plus a **different** historical native-CSAPI read path specialized to Bennett's Point. That was insufficient to show an unrelated CSAPI producer could publish the same evidence standing, as an unknown Profile-aware client would need to discover it rather than receive a preselected file. Step 41R-05 creates a separate read-only HTTP producer that publishes genuinely **CSAPI Part 1 GeoJSON resources** and lets a client follow **registered, resource-specific typed links** to a separate, versioned **project-only source-evidence description**.

The producer exposes two *deliberately unlike* source situations: **Dragino S31-LB** as a manufacturer/reference **\`Procedure\`** without a location or installed serial, and **Bennett's Point \`acebpmet\`** as a real historical station **\`System\`** with an operator-stated station site position. In each case the extra whole-System claims appear in a linked project evidence description; they are *not* inserted into the native GeoJSON as imaginary OGC fields. A resource can therefore be a schema-valid native Procedure/System while its richer evidence is qualified as **producer asserted, original publisher not independently authenticated**.

**This is a successful producer experiment, not the full end-state.** There is still no independent third-party Profile-aware client, no general Glaux CSAPI native source→Profile→UI path in application code, and no fully certified /conformance class advertisement. The previous source-precision and whole-System completeness holds stay explicit. **Gate E/F NOT CLOSED**; the new result is enough to justify attempting **Step 41R-06**, not enough to publish a portable adopted OGC application Profile as proven.

## 3. Original standard and schema authority, including actual negative checks

The [original published OGC 23-001 Part 1 v1.0](https://docs.ogc.org/is/23-001/23-001.html) says that **Procedures** describe system models/methodologies, while **Systems** describe instances (Part 1 §§9 and 13); GeoJSON **Req 77** specifies \`application/geo+json\`; **Req 81/82** govern System schema/mapping, and **Req 85/86** Procedure schema/mapping (Part 1 §19.1). The original [OGC API – Common Part 1 v1.0](https://docs.ogc.org/is/19-072/19-072.html) and [RFC 8288](https://www.rfc-editor.org/rfc/rfc8288) provide Web linking, while [RFC 6906](https://www.rfc-editor.org/rfc/rfc6906) allows a representation to indicate extra Profile conventions without altering its existing media-type meanings. The Profile sidecar's SOURCE_FACT, SOURCE_EXAMPLE, DERIVED, UNKNOWN, original-event/copy equivalence and producer verification semantics remain **a new project convention**, not existing required SensorML/SWE/CSAPI members.

**Exact original schema traceability:** The unchanged [original OGC release v1.0.0 schema tree](https://github.com/opengeospatial/ogcapi-connected-systems/releases/tag/v1.0.0) was copied, alongside the original [GeoJSON Feature and FeatureCollection](https://geojson.org/schema/) schema snapshots, into the test producer's [schema-vendor](Step41R05_Native_Producer/schema-vendor). Their [test provenance and SHA identifiers](Step41R05_Native_Producer/README.md#original-standard-clauses-and-pinned-schemas-not-generated-project-syntax) are recorded. The test harness adapts **in-memory relative \`$ref\` resolution**, not normative schema content or constraint values; it validates both individual resources and collection responses using \`jsonschema==4.26.0\` with URI format checking.

**Actual negative and trust protections, not just HTTP 200:**

- HTTP POST/PUT/PATCH/DELETE return **405**; the producer exposes **no actual \`/observations\`, \`/commands\`, \`/controlstreams\`, or \`/deployments\` routes**. Unsupported native IDs, Profile versions and Accept media return **404/406**, respectively.
- Source-evidence sidecars bind **the exact native URI and integrating resource UID**. Deliberately changing a sidecar's \`describes.uid\` is rejected by the project test. The 21 Dragino selected source assertions remain reference-only, and the Bennett sidecar retains two original NOAA events/four digital representations, raw padded source QC and unknown original mean timing.
- HTTP \`Link\` headers match body \`links\`, and are exposed to script via CORS. The isolated loopback producer rejects non-loopback binds and sanitizes untrusted Host headers. No browser was actually launched in Step 41R-05, so this is HTTP protocol/visibility evidence, **not Chromium cross-origin UI proof**.
- [Earlier Step 41R-02 producer source oracles](Step41R02_Producer_Source_Assertion_Contract_and_Oracles_03NOV2026.md) were separately re-executed **and passed** on the four *unchanged original source packets* with all original false examples and spoofed issuer tests. They remain **controlled-source consistency tests, not independent digital issuer signatures or proof of all 182 donor artifacts**.
