## 1. What improved in operator terms

For **Dragino**, the small original packet was capable of describing one externally cabled **three-metre SHT31 reference probe** producing two different environmental properties, manufacturer-rated battery capacity, and a printed scalar sample. It had **omitted** important source-known parts of the whole design: **20-minute default uplink**, **separate LoRaWAN FPort 2 current, FPort 3 retained-history and FPort 5 device-status message types**, status voltage/firmware **field definitions**, LoRaWAN/Bluetooth/UART communications and the supported **AT+TDC** interval command. The expanded packet now carries these explicitly, so the existing generic interface can display them as design, messages, configuration/capabilities and source evidence. The example `AT+TDC=60000` is **printed example syntax in milliseconds**, not an applied 60-second interval; `configuration.effective_setting` remains UNKNOWN, and no actual device Observation or Command is invented.

For **AirGradient**, the original packet distinguished **two physical reference PMS5003 modules on PM1/PM2 hardware sockets** from the `pm01/pm25/pm10` data-property names. That remains intact. The new packet also declares the source-attested **ESP32-C6 main board, SUNX/SenseAir CO₂, SGP41, SHT40, AlphaSense NO₂/O₃ sensing assembly and CE cellular card** as distinct **design/reference participants**, not verified installed serial-numbered equipment. It includes the documented **10 W solar-panel rating** and **three 3,500 mAh 18650 Li-ion cells in series (3S)** without inferring a measured charge or wrongly adding nameplate cell capacities into a 10,500 mAh pack.

AirGradient's **2.4 GHz Wi-Fi** and **LTE Cat 1** arrangements, README **Cellular** network default, **Cellular 3-minute samples / nominal 9-minute batches with volatile retry cache** versus **Wi-Fi JSON every 3 minutes without retransmission**, and the pinned **firmware source revision** are now distinct assertions. These are **different source-defined modes/behaviors**, not one simultaneous real device session. The project still has no authenticated installed device, actual deployed firmware, gas calibration outcome or operating record; the previously printed `pm25=27.7` remains **SOURCE_EXAMPLE**, not performed telemetry.

The two expanded cases are still interpreted by **the same generic Glaux reader and existing Resource Details renderer**. The additions are generic concept names such as `configuration.documented_default`, `output.message_type`, `communications.documented_reporting`, `power.design_specification`, and `software.reference_revision`; these are **local, project-authored research vocabulary, not OGC native properties or DIM classes**. Source/case-specific comparisons are test **oracles**, not hidden manufacturer-name conditions inside the shared interpretation code.
