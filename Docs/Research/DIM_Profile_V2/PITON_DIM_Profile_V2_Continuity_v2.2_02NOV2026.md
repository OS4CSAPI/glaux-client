## 1. What the owner is actually trying to achieve

The ultimate goal is **one implementation-independent Domain Information Model (DIM)** describing equipment-realized sensing Systems and their relevant whole-System characteristics and relationships; **one separate, testable OGC API – Connected Systems (CSAPI) Profile** carrying these meanings using appropriate existing OGC standards; and **one shared, profile-aware Glaux Resource Details interpretation** that preserves the differing manufacturer experiences without a vendor-coded UI per system. Generic CSAPI resource lists alone do not satisfy that goal. **An observed missing field could be lost at source integration, server representation, or client interpretation—do not assume which without checking source→DIM→Profile→client.**

The research deliberately avoided fixing an overarching domain name, forced chassis superclass, five V1 candidate foundations, power-first categorization or predetermined UI tabs. The working phrase **system and sensor and equipment** remains provisional; the technical direction below is **not a new approved root label**. See [original purpose and intended outcome](DIM_Profile_V2_Problem_and_Outcome_Baseline_v0.1_28OCT2026.md).

## 2. Phase C decision: what Gate C actually established

**Gate C is REACHED WITH BOUNDED SCOPE, SOURCE-AUTHORITY AND TEST LIMITATIONS**. Step 10 constructed three alternative whole-System primary boundaries: **A** individual physical unit/assembled product; **B** sensing/observing/reporting arrangement; **C** continuing installed station. Steps 11–14 independently examined original donor sources before Step 15 compared them with all four cases. **Each A/B/C gives a valuable different view but fails as a universal exclusive root.**

**Preferred working structural approach D for the first DIM draft:** describe **one explicitly bounded, source-attested equipment-realized sensing System/arrangement focus**, and relate separately identifiable **physical equipment, observing/processing functions, host/installation, management, commands, publisher/proxy and source records** only when relevant and originally supported. This is **NOT a decision to “model everything”**: one must establish the focus and evidence grade, limit inclusion to relevant supported roles, distinguish type/reference design from actual installed instance, and preserve relationship/identity kinds and unknowns. There is **no adopted mandatory DIM class list or cardin­ality, no final chassis ontology, no CSAPI mapping or DataStream owner**, and no built client proof. **D must be challenged in Phase D**; if a source cannot be faithfully represented, narrow/revise it rather than rewrite the source.

**Case evidence ceilings preserved:**

- **Dragino S31-LB:** manufacturer reference **node plus one externally cabled SHT31 providing two properties**, documented message types/settings/power, **not** authenticated individual installed hardware.
- **AirGradient Open Air Max:** manufacturer **gas-equipped multi-module reference monitor**, two physical PMS5003 units and multiple outputs, power/network/firmware/cloud examples **not one joined calibrated operating history**.
- **Campbell CR1000X + first-generation ClimaVue 50:** **separately identifiable logger/sensor reference pairing**, fourteen published SDI-12 output positions and unrelated publisher logger Status example; **not** a verified station, deployed program or observed weather data.
- **Bennett's Point / acebpmet:** **actual continuing historical station**, CR1000X logger serial 13916, transmitter 2335, EE181 **222016000109CE** before 16 Apr 2024 and returning **21281600077814** after; only **two original selected NOAA air-temperature means**, with project **derived** nominal UTC windows and serial attribution. Its **four test-server Observation resources represent just two source measurements**. Exact swap minute, probe-specific geometry, original result availability time and complete operating history are **UNKNOWN**.

**Coverage controls:** AAS v3.2 distinguishes asset and digital Shell/type/instance; OPC UA Devices/PA-DIM equipment/physical connection/signal/condition; ISA external visibility and CIC mediation; The Open Group SOSA multi-element Sensor, separate Host, functional/product/management; IEEE 1451 detailed module/channel TEDS at public technical evidence level (full 2024 normative SHALLs not verified); SensorML 3.0 processes/typeOf/history/deployment; SAPIENT v2 capabilities/current state/task/acknowledgements; OMS 3.0 individual Observer/Procedure/Host/Deployment and distinct phenomenonTime/resultTime; W3C SOSA-SSN 2017 Recommendation with **separate 2026 Working Draft**; WoT TD/Architecture 1.1 description, proxy and twin. **The original four donor iterations were targeted editions/passages only**, not an exhaustive audit or standard “vote.” Two SAPIENT discrepancies remain open: BSI **config_data field 9 versus pinned protobuf tag 10**, and wrapper **content time versus sent time**.

**Gate C does NOT mean:** a complete same-unit/same-config/same-history dataset, vendor conformance, physically authenticated identities for three reference cases, executable data transformations, solved CSAPI **station-led versus probe-led DataStream** issue, true Bennett resultTime, verified W3C draft migration, or publication readiness. A/B/C remain useful distinct perspectives. The relational approach D is merely **selected for falsifiable candidate drafting**.
